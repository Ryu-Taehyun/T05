# RELAY 인수인계 — A → B

1. 목표: 로그인이나 설치 없이 동작하는 단일 HTML 작업 보드. 다른 환경에서도 JSON 파일로 작업과 맥락을 복원한다. 기존 과제 3·4 자료가 없어 신규 기반을 만들었다.
2. 위치: index.html의 model 스크립트가 데이터 처리, ui 스크립트가 화면과 저장. report.html은 최종 보고서로 B 검증 후 A가 만든다. 외부 의존성 없음.
3. 완료: A가 추가/삭제/단계 변경/검색/진행률/자동 저장/메모/JSON 내보내기를 구현. 샘플 3개는 시연 데이터다.
4. 남은 일: B는 importFile 변경 이벤트를 구현한다. 크기 2MB 제한, JSON 검증 후 교체 확인, 취소·오류 시 상태 유지, 성공 시 메모와 보드 동기화 및 저장. 기존 저장소 오류로 storageReady=false이면 저장을 억지로 재개하지 않는다.
5. 고정 검사 10개: T01 샘플 3개와 완료율 33%. T02 공백 제목 거부 및 정상 추가. T03 단계 변경과 완료율. T04 삭제. T05 제목/메모 검색. T06 저장 후 새 실행 컨텍스트에서 복원. T07 세 가지 메모의 JSON 왕복. T08 잘못된 JSON/중복 ID/잘못된 상태 거부. T09 B의 새 환경에 A 내보내기 파일 복원 후 T01~T08 재실행. T10 불러오기 성공/취소/잘못된 파일/2MB 초과 시 원본 보존. 동일한 공통 상황: 샘플 보드에서 '회의 자료 정리'를 추가하고 단계 변경, 메모 작성, 파일로 새 환경에 옮김. 브라우저 실제 클릭 검사 여부와 VM 검사 여부를 구분한다.
6. 실행 및 위험: HTML을 브라우저에서 열면 된다. localStorage는 브라우저·파일 위치에 따라 다르고, 브라우저 데이터 삭제 시 사라지므로 파일 내보내기를 쓴다. 동시 편집·서버·실제 LLM 연동은 범위 밖이다. innerHTML 대신 textContent로 사용자가 입력한 내용을 표시한다. 저장소를 읽지 못할 때 기존 값을 덮어쓰지 않는다.
7. 다음 행동 및 완료 기준: B는 이 문서와 저장된 파일만 읽고 불러오기를 완성하고 동일 검사 10개를 실행한다. 독립 Node VM 등 실행 가능한 검증 도구를 작성해 결과를 B-RESULT.md에 사실대로 기록한다. A는 그 결과로 공개 비교 보고서(로컬 HTML)를 만든다. 사용자에게 최종 결과물과 소스를 전달. 실제 브라우저 검사를 하지 않았다면 통과했다고 쓰지 않는다.
