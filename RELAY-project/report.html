결과물과 범위

RELAY 작업 보드 · 7항목 인수인계 문서 · 이어받기 검증 기록 · 고정 검사 소스

할 일·진행 중·완료 관리, 제목과 메모 검색, 진행률, 자동 저장, 맥락 메모, JSON 내보내기·불러오기를 제공합니다. index.html 자체가 실행 파일이자 전체 소스입니다.

기존 과제 3·4의 자료가 없어 사용자의 승인으로 새 기반을 제작했습니다. 공개 배포 주소는 생성하지 않았습니다. 로그인 없이 열 수 있는 로컬 파일이며, 실제 LLM API 연동·동시 협업·서버 저장 기능은 포함하지 않습니다.

이어받은 순서

  1. A 시작: 데이터 구조와 공통 사용 상황, 검사 10개를 먼저 고정하고 보드 및 내보내기 구현.
  2. A 인계: 8개 기반 검사 통과 후 소스, A-handoff.json, HANDOFF.md 저장.
  3. B 시작: 이전 대화 이력 없이 별도 AI 실행에 저장 파일 위치만 전달. B가 문서와 소스를 읽고 불러오기 기능 구현.
  4. B 완료: 새 실행 환경에서 A의 인수인계 파일을 복원하고 고정 검사 및 불러오기 경로 검증.

A/B는 이 환경 안의 서로 분리된 AI 실행입니다. 서로 다른 LLM 제품을 연동한 실험이나 모델 성능 비교를 의미하지 않습니다.

짧은 확인 방법 · 4줄

① 위치: index.html을 브라우저에서 열고 ‘새 작업’을 선택합니다.
② 행동: 작업 추가 → ‘완료’로 변경 → 인수인계 파일을 내보내 다른 브라우저의 RELAY에서 불러옵니다.
③ 통과 모습: 작업·단계·세 가지 맥락 메모가 복원되고 완료율이 동일합니다.
④ 안 될 때 모습: 잘못된 파일은 오류를 표시하며 기존 보드를 유지합니다. 자동 저장 실패 시 파일로 내보내 보관하라는 메시지가 나옵니다.

이름을 가린 측정표

동일한 기준으로 제작 시점 X와 이어받기 후 Y를 비교합니다. 모델 품질 순위가 아닌 기능 완성도 측정입니다. 미구현 항목은 실패와 구분합니다.

공통 사용 상황: 샘플 보드에 ‘회의 자료 정리’ 추가, 단계 변경, 메모 작성, 파일로 새 환경에 전달. 자동 검증은 Node의 분리된 JavaScript 실행 컨텍스트 및 화면 요소 대역을 사용합니다. 브라우저에서의 실제 클릭·모바일 배치·다운로드 창은 자동 검증과 구분합니다. 이 환경에서는 미리보기 연결이 차단되어 실제 브라우저 시각 검사를 완료하지 못했습니다.

판단 기록 · 3줄

AI에게 맡긴 일: 주제 제안, 화면과 기능 구현, 인수인계 문서 작성, 분리 실행 및 검증.
사용자가 직접 판단한 일: 기존 자료 없이 AI가 주제를 정해 새 프로젝트를 만들도록 승인. 결과물의 최종 사용성 평가는 아직 받지 않았습니다.
AI 제안을 따르지 않은 일: 사용자가 거절한 제안은 기록된 것이 없습니다. 로컬 단일 파일 방식은 제작 과정의 선택이며 사용자 판단으로 대신 기록하지 않습니다.

도구 선택 기준

설치와 계정 없이 바로 쓰도록 HTML·CSS·JavaScript를 사용했습니다. 작업 이동에는 JSON을 사용해 내용과 단계·메모를 함께 보존합니다. Node 검사는 같은 기준을 별도 실행 환경에서 반복하기 위해 사용했습니다. 시연 데이터는 실제 사용자의 기록이 아닙니다.
